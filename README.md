# موقع مدرسة شهيد حسن حمدي + لوحة تحكم أدمن

## هيكل الملفات
```
/index.html        ← الصفحة نفسها (HTML بس)
/css/style.css      ← كل التنسيقات (كان قبل كده جوه <style> في نفس الملف)
/js/site.js          ← كود الموقع العادي (المدرسين، الطلاب، الصفحات، الأنيميشن...)
/js/admin.js         ← كود لوحة الأدمن بس (منفصل تمامًا عن كود الموقع)
/api/                ← دوال السيرفر (Vercel functions) اللي بتكلم قاعدة البيانات
/api/_validate.js    ← فحص وتنضيف كل المدخلات على السيرفر
/api/_auth.js        ← التحقق من كلمة سر الأدمن (مقارنة timing-safe)
/tests/              ← اختبارات تلقائية (npm test)
/schema.sql
/vercel.json         ← security headers + قواعد الكاش (بتتطبق تلقائيًا على Vercel)
/manifest.webmanifest ← تعريف الـ PWA (اسم التطبيق وأيقوناته لما يتثبّت على الموبايل)
/sw.js               ← service worker: بيخزّن الملفات الثابتة محليًا (فتح أسرع في الزيارات الجاية)
                       ⚠️ لو عدّلت أي ملف ثابت، زوّد رقم CACHE_VERSION جواه
/robots.txt          ← قواعد أرشفة جوجل
/sitemap.xml         ← خريطة الموقع لمحركات البحث
/icons/              ← أيقونات التثبيت (192/512) — maskable
/og-image.png        ← صورة المعاينة اللي بتظهر لما الرابط يتشار على واتساب/فيسبوك
/package.json
/README.md
```
كل حاجة كانت متكدسة في ملف HTML واحد بقت متقسمة على حسب نوعها. `js/admin.js`
مبيتحطش في `index.html` — `site.js` بيحمّله تلقائيًا (lazy-load) أول مرة حد
يفتح `#/admin`، عشان حجمه (~44KB) متنزّلش على كل زائر. وبيستخدم دوال من
site.js، وده مضمون لأنه دايمًا بيتحمّل بعده.

🔗 رابط الموقع: `https://nu-rsch.vercel.app` — مسجّل في وسوم `og:url` و
`canonical` و `og:image` في `index.html` وفي `robots.txt` و `sitemap.xml`.
لو الرابط اتغيّر يومًا، حدّث الخمس أماكن دول.

## اللي اتعمل
- الموقع الأصلي زي ما هو بالظبط (نفس التصميم والحركات)، بس بقى بيقرأ المدرسين
  والطلاب والصور من قاعدة بيانات بدل ما تبقى مكتوبة جوه الكود.
- لو قاعدة البيانات لسه مش متوصلة أو حصل خطأ، الموقع بيرجع تلقائيًا للبيانات
  الافتراضية الموجودة في الكود عشان الموقع متعطلش أبدًا.
- لوحة أدمن **مخفية تمامًا** — مفيش أي زرار أو لينك ليها في الموقع. بتتفتح بس
  لو حد كتب بنفسه `/#/admin` في آخر الرابط.
- من لوحة الأدمن تقدر: تضيف/تعدل/تمسح مدرسين، تضيف/تعدل/تمسح طلاب أوائل،
  وتضيف/تمسح صور ذكريات — وكل حاجة بترفع للموقع فورًا لأي زائر.
- الدخول للوحة محمي بكلمة سر واحدة (مش يوزر باسورد كامل، بس كافي لموقع مدرسي
  بسيط). كل طلب تعديل بيتأكد من كلمة السر على السيرفر نفسه.

## خطوات الرفع (من الصفر لحد الموقع شغال)

### 1) قاعدة البيانات (Neon)
1. سجل في https://neon.tech وأنشئ مشروع جديد (Database).
2. من الـ SQL editor بتاعهم، افتح ملف `schema.sql` من المشروع ده وشغّله مرة واحدة
   (بينشئ 3 جداول: teachers, students, photos).
3. **(اختياري بس موصى بيه)** شغّل ملف `seed.sql` كمان — ده فيه كل المدرسين
   (25) والطلاب الأوائل (6) اللي كانوا مكتوبين في الكود الأصلي، منقولين
   كـ INSERT statements جاهزة. لو شغّلته، هتلاقيهم فورًا في لوحة الأدمن تقدر
   تعدّل فيهم أو تمسح أو تضيفلهم صور من غير ما تكتبهم من الأول. شغّله *مرة
   واحدة بس* (لو شغلته تاني هتتكرر البيانات مرتين).
4. من صفحة الـ Connection String، انسخ الرابط اللي شكله:
   `postgresql://user:pass@ep-xxxx.neon.tech/dbname?sslmode=require`
   — ده هو اللي هنحطه في `DATABASE_URL`.

### 2) GitHub
1. اعمل ريبو جديد وارفع كل ملفات المشروع ده فيه (index.html, api/, package.json,
   schema.sql, .gitignore...) — **متضيفش** ملف `.env` لو عملته، خليه بس عندك محليًا.

### 3) Vercel
1. سجل في https://vercel.com وقول "Add New Project" واختار الريبو اللي رفعته.
2. Vercel هيكتشف الملفات تلقائيًا (مفيش build step مطلوب، الموقع static + api/).
3. قبل الديبلوي (أو بعده من Settings -> Environment Variables) ضيف:
   - `DATABASE_URL` = رابط Neon اللي نسخته فوق
   - `ADMIN_PASSWORD` = كلمة سر قوية من اختيارك (احفظها كويس، هي مفتاح اللوحة)
4. اعمل Deploy. بعد ما يخلص، هيديك رابط زي `your-school.vercel.app`.

### 4) الدخول للوحة الأدمن
افتح: `https://your-school.vercel.app/#/admin`
وادخل بكلمة السر اللي حطيتها في `ADMIN_PASSWORD`.

## ملاحظات مهمة
- **كلمة سر الأدمن**: احفظها في مكان آمن. أي حد يعرفها يقدر يتحكم في الموقع
  بالكامل. لو حسيت إنها اتسربت، غيّرها من Environment Variables في Vercel
  وهتشتغل فورًا من غير أي تعديل في الكود.
- **الصور**: بتتخزن كـ base64 جوه قاعدة البيانات نفسها (مفيش خدمة تخزين ملفات
  منفصلة)، والفرونت بيصغّر أي صورة ترفعها تلقائيًا (لحد ~900px) قبل الرفع عشان
  تفضل قاعدة البيانات خفيفة. ده كويس لعدد صور معقول (كام مية)، لو حبيت تحط آلاف
  الصور يبقى الأفضل بعدين ننقل التخزين لـ Vercel Blob بدل قاعدة البيانات.
- **بيانات المدرسين والطلاب القدام**: البيانات اللي كانت مكتوبة جوه الكود قبل
  كده لسه موجودة كـ "بيانات احتياطية" (DEFAULT_TEACHERS / DEFAULT_STUDENTS) —
  الموقع بيعرضها لحد ما تضيف بيانات حقيقية من لوحة الأدمن، وبعدين بيعرض بيانات
  قاعدة البيانات تلقائيًا.

## آخر إصلاحات (صور المعلمين + لوحة الأدمن على الموبايل + تحسين الواجهات)

### 1) صورة المعلم مكانتش بتظهر
- **السبب**: كل صور المدرسين/المدير كانت متخفية بـ `display:none` في CSS
  وبتظهر بس لما الـ `onload` بتاع الصورة يضيف كلاس `.has-photo`. ومع
  `loading="lazy"` معناها إن العنصر مالهوش صندوق في التخطيط، فالمتصفح عمره ما
  يعتبره "داخل الشاشة" وعمره ما يبدأ تحميله أصلاً — يعني الـ `onload` اللي
  المفروض يظهر الصورة هو نفسه اللي مستني الصورة تتحمّل (فخ بيضة وفرخة).
- **الحل**: الصور بقت تتخفي بـ `opacity:0` (بدل `display:none`) عشان العنصر
  يفضل محتفظ بمكانه والتحميل يشتغل، وصورة لوحة الأدمن (data URL) بتترسم
  **ظاهرة من أول لمسة** مع كلاس `.has-photo` جوه الـ HTML نفسه بدون أي اعتماد
  على حدث تحميل. ولو الصورة اتكسرت بيرجع شكل الـ placeholder تلقائيًا
  (`photoFailed`).
- نتيجة عملية: **أي صورة رفعتها قبل كده من اللوحة لسه محفوظة في قاعدة البيانات
  وهتظهر دلوقتي من غير ما ترفعها تاني**.
- زيادة على كده: الصورة بقت فوق طبقات التدرّج الزخرفية (كانت تحتها فالتدرّج
  الغامق كان بيغطي جزء منها)، ولو الصورة حمّلت قبل ما الصف يترسم بيتظبط الحالة
  عن طريق فحص `img.complete` (دالة `syncPhotoState`).

### 2) لوحة الأدمن على شاشة التلفون
- التابات بقت 3 أعمدة متساوية بتملأ الصف (بدون سكرول أفقي).
- كروت المدرسين/الطلاب/الصور بقت **صف واحد لكل عنصر**: صورة مصغّرة + اسم واضح
  + زرّي تعديل/حذف أيقونيين بحجم 42px (قابلين للمس)، بدل عمودين مزنوقين.
- فورم الإضافة/التعديل بقى bottom sheet بنسبة ارتفاع `92dvh`، والحقول هي اللي
  بتسكرول جواه، وأزرار «حفظ/إلغاء» ملزوقة تحت الشاشة دايمًا (كلاس
  `.adm-form-actions` — كان قبل كده selector هشّ بيدور على `style` الـ div).
- مراعاة `env(safe-area-inset-*)` للـ notch والـ home indicator، ومنع تكبير
  iOS التلقائي للحقول (`font-size:1rem`)، ومنع سكرول الصفحة من ورا اللوحة.

### 3) تحسينات الواجهات العامة
- عناوين الصور في معرض الذكريات كانت بتظهر بالـ hover بس → بقت تبان على
  التلفون بشكل دايم.
- صورة المدرس على الموبايل بقت «بوستر» بنسبة 4:3 بدل شريط 180px كان بيقص الوش.
- الطلاب على الموبايل: عمود واحد مريح بدل عمودين مزنوقين.
- إصلاحات حقيقية: كروت الطلاب كانت بتتكرر لو بيانات الـ API وصلت بعد ما الصفحة
  اترسمت (المصفوفة مكانتش بتتفضى)، وكان بيتضاف `setInterval` جديد كل مرة
  تُرسم فيها الصفحة.
- إيقاع رأسي متسق لعناوين الأقسام، وحالة `:focus-visible` واضحة للكيبورد،
  وتباين أحسن للفوتر وأدوات الإغلاق في الوضع الفاتح، وقائمة التصفية ما تعديش
  حدود الشاشة.

> ملاحظة بعد الرفع: اعمل Deploy جديد على Vercel (لأن الملفات ثابتة وبتتكاش
> على المتصفح) وبعدين `Ctrl + F5` مرة واحدة عشان تضمن إن الـ CSS/JS الجداد
> هما اللي اتحمّلوا.

## اختبارات (اختيارية)
مجلد `tests/` فيه 3 اختبارات بتتشغل بـ Node من غير أي مكتبات إضافية:
```
npm test
# أو كل واحد لوحده
node tests/photos.test.js      # منطق صور المدرسين (بيحمّل js/site.js الحقيقي)
node tests/layout.test.js      # فحص CSS الموقع + CSS لوحة الأدمن المولّد جوه admin.js
node tests/security.test.js    # حماية XSS + فحص مدخلات السيرفر + المصادقة
```
الاختبارات دي ثابتة من غير قاعدة بيانات، وبتتأكد إن فخ `display:none` + `loading="lazy"`
اللي كان بيمنع ظهور الصور مايرجعش تاني بالغلط، وإن الحماية ضد XSS شغالة.

## جولة الفحص الشامل — أمان وصلابة (أحدث جولة)

### 1) حماية من XSS المحفوظ (Stored XSS)
- قبل الجولة دي، كل بيانات قاعدة البيانات (أسماء، نبذات، صور) كانت بتتطبع خام
  جوه `innerHTML` — أي نص فيه `<` أو `"` كان بيكسر الصفحة، ولو حد وصل لقاعدة
  البيانات كان هيقدر يزرع كود خبيث يشتغل عند كل زائر.
- دلوقتي: كل قيمة نصية بتعدي على `escapeHtml()` قبل الطباعة (في `site.js`
  و`admin.js`)، والصور بتعدي على `safePhotoSrc()` اللي بترفض أي قيمة مش
  `data:image/*;base64` حقيقية — فبيترسم الـ placeholder بدل أي محتوى مشبوه.

### 2) تحقق من المدخلات على السيرفر (`api/_validate.js`)
- السيرفر بقى بيفحص كل حقل: النصوص ليها حد أقصى للطول، الصور لازم تكون
  data:image سليمة وتحت ~2 ميجا (أقل من حد Vercel للـ request body البالغ
  4.5MB — يعني مفيش 413 مفاجئ)، والتواريخ لازم تكون بصيغة YYYY-MM-DD.
- أي صورة مرفوضة بترجع خطأ 400 واضح بدل ما تتخزن بايظة أو تترمي بصمت.

### 3) تحصين المصادقة
- مقارنة كلمة السر بقت **timing-safe** (`crypto.timingSafeEqual`) — مفيش
  تسريب لمعلومات عن طريق فرق زمن الرد.
- تأخير 400ms عند فشل تسجيل الدخول بيبطّئ أي تخمين آلي (brute force).
- ردود الخطأ 500 مبقتش بتسرّب تفاصيل داخلية عن قاعدة البيانات للعميل.

### 4) Security headers (`vercel.json`)
- `X-Content-Type-Options: nosniff` + `X-Frame-Options: DENY` +
  `Referrer-Policy` + `Permissions-Policy` — بتتطبق تلقائيًا مع أول Deploy
  بعد الجولة دي، من غير أي إعداد إضافي.

### 5) إصلاحات صلابة
- صور الذكريات كانت ممكن تفضل مخفية لو الزائر فتح الصفحة قبل وصول بيانات
  الـ API (الكروت الجديدة مكانتش بتتراقب بالـ IntersectionObserver) — اتصلحت.
- فلتر المدرسين المختار بيفضل شغال بعد ما البيانات الحية توصل (كان بيتصفّر).
- حقل تاريخ الميلاد في فورم تعديل الطالب كان بيفضل فاضي لو قاعدة البيانات
  رجّعت التاريخ بصيغة ISO كاملة — بقى بيتطبع صح.
- `calcAge` مبقتش ترجع `NaN` لو التاريخ مش مفهوم.
- الـ SVG gradient ids في كروت المدرسين بقت فريدة لكل كارت (كانت بتتكرر
  بين مدرسين لهم نفس الحرف وطول الاسم).
- صور PNG الشفافة اللي بتترفع بقت بخلفية بيضا بدل السودا (JPEG مبيدعمش
  الشفافية).
- لو كلمة سر الأدمن اتغيرت وجلستك انتهت (401)، اللوحة بترجعك لشاشة الدخول
  فورًا بدل ما تعرض "مفيش عناصر" وتلخبطك.
- الأيقونة الافتراضية للمدرس الجديد بقت أول حرف من الاسم بعد "أ." (كانت
  بتاخد آخر حرف من الاسم كله).

### 6) وصولية وأداء
- كروت المدرسين وصور وفيديوهات الذكريات بقت تتفتح بالكيبورد كمان
  (`tabindex` + Enter/Space + `role="button"`).
- لينكات `#` المؤقتة مبقتش بتوسّخ الـ history ولا بتفتح تبويبات فاضية.
- اتضاف `preconnect` لـ fonts.gstatic.com (الخطوط بتحمّل أسرع شوية).

## تحديث الواجهة الرئيسية + حل نهائي لمشكلة "التحديثات مش بتظهر"

### 1) إعادة تصميم الصفحة الرئيسية
- **قسم «استكشف الموقع»**: ٤ بطاقات كبيرة (المدير والمدرسون · الطلاب المتفوقون ·
  ذكريات المدرسة · عن الموقع) بأيقونات SVG وتأثير hover ذهبي — بتحوّل الرئيسية
  لبوابة تنقل حقيقية بدل ما تكون مجرد شاشة ترحيب.
- **قسم «عن المدرسة»**: عنوان قسم رسمي + أيقونات SVG بإطار ذهبي لكل بلوك
  بدل الإيموجي.
- **بانر مشاركة** قبل الفوتر: يشجّع الزائر يشارك صوره واقتراحاته (يفتح نافذة
  التواصل الموجودة).
- **لمسات الـ hero**: شبكة هندسية خفيفة فوق التدرج + زر «استكشف الموقع»
  بينزل بسلاسة لقسم البطاقات.
- كل الأقسام الجديدة متجاوبة (٤ ← ٢ ← ١ عمود) ومحترمة لـ `prefers-reduced-motion`.

### 2) الصور المرفوعة من الأدمن — توضيح نهائي
- **اسم ملف الصورة غير مهم إطلاقًا.** اللوحة بتحوّل أي صورة لـ JPEG مضغوطة
  وتخزنها جوه قاعدة البيانات نفسها (`photo_data`)، فبتظهر في كارت المدرس
  وصفحة معلوماته فورًا. نظام ملفات `photos/1.jpg` القديم مجرد احتياطي للبيانات
  الافتراضية بس.
- اتضاف اختباران في `tests/photos.test.js` بيحاكيا صفحة معلومات المدرس نفسها
  (`openTeacherPage`): الصورة المرفوعة بتظهر فورًا، وأي قيمة مش `data:image`
  بتترفض.

### 3) إصلاح دائم لمشكلة «بعمل تعديل ومبيظهرش على الموقع»
- `vercel.json` بقى فيه `Cache-Control: no-cache, must-revalidate` لـ
  `/` و `/js/*` و `/css/*` — يعني بعد أي Redeploy المتصفح بيسحب أحدث نسخة
  تلقائيًا من غير Ctrl+F5 (مع إعادة تحقق سريعة بالـ ETag فمفيش بطء).
- لسه مطلوب بعد أي تعديل في الكود: **Redeploy من لوحة Vercel** — التعديلات
  المحلية مبتظهرش على الرابط المنشور لوحدها.



## جولة الوضع الفاتح + توافق Samsung Internet

### 1) الوضع الفاتح بقى حقيقي
- كان بيغيّر متغيرات الخلفية والنص بس، وسايب أسطحًا كتير غامقة مكتوبة يدويًا
  (النافبار، الـ hero، كروت الإحصائيات والاستكشاف، شريط التنقل السفلي…)
  فكان الشكل مشوّه. اتضاف قسم «إعادة تلوين الوضع الفاتح» في آخر `css/style.css`
  بيعيد تلوين كل الأسطح دي لهوية عاجية/ذهبية متناسقة.
- اتضاف متغير `--shc` (مكوّنات لون الظل): أسود في الغامق، بني دافئ في الفاتح —
  فالظلال بقت ناعمة على الخلفية الفاتحة بدل الأسود الثقيل.
- نصوص كانت بتختفي على الفاتح (عناوين الـ hero الشفافة، أيقونات وعناوين الشريط
  السفلي، عناصر قائمة الفلتر، تسميات الإحصائيات) بقت بتتبع متغيرات النص.

### 2) توافق Samsung Internet والمتصفحات الأقدم
- كل `backdrop-filter` بقى له توأم `-webkit-backdrop-filter` (٧ مواضع).
- إضافة fallback بـ `vh` قبل أي `svh` كان ناقصه.
- `-webkit-tap-highlight-color:transparent` لإخفاء وميض اللمس الافتراضي.
- `text-wrap` وغيرها من الخصائص الحديثة بتتجاهل بأمان على القديم (مفيش كسر).

### 3) اختبارات جديدة
- `tests/layout.test.js` بقى بيتأكد من وجود قواعد الوضع الفاتح الأساسية
  ومن إن كل `backdrop-filter` له توأم `-webkit-` (فحص عدّ آلي).

## نظام الشكاوى والاقتراحات (بديل الواتساب)

نموذج «الشكاوى والاقتراحات» في الموقع (من القائمة الجانبية أو زر الصفحة الرئيسية) بيحفظ الرسالة في قاعدة البيانات مباشرة — مفيش واتساب ولا أي خدمة خارجية في وش الزائر.

**اللي الزائر بيكتبه:** نوع الشكوى (من قائمة ثابتة) + الاسم بالكامل + رقم موبايل عليه واتساب (لازم رقم مصري صحيح `01xxxxxxxxx`) + التفاصيل (10 حروف على الأقل) + لحد 5 صور اختيارية (بتتظغط تلقائيًا في المتصفح قبل الإرسال لـ ~120KB للصورة).

**في لوحة الأدمن:** تبويب «الشكاوى» بيعرض كل رسالة (النوع، الاسم، الرقم مع زر «رد واتساب» جاهز، التفاصيل، والمرفقات اللي بتتكبّر بالضغط) مع إمكانية تعليمها «تمت المراجعة» أو حذفها نهائيًا.

### خطوة التشغيل (مرة واحدة)

شغّل الكود ده في Neon SQL Editor (موجود كمان في آخر `schema.sql`):

```sql
CREATE TABLE IF NOT EXISTS complaints (
  id          SERIAL PRIMARY KEY,
  type        TEXT NOT NULL,
  name        TEXT NOT NULL,
  phone       TEXT NOT NULL,
  details     TEXT NOT NULL,
  images      JSONB DEFAULT '[]'::jsonb,
  status      TEXT DEFAULT 'جديدة',
  created_at  TIMESTAMPTZ DEFAULT now()
);
```

**الحماية:** الفحص الحقيقي على السيرفر في `validateComplaint` جوه `api/_validate.js` (نوع من قائمة ثابتة، موبايل مصري، 5 صور كحد أقصى بإجمالي ~3MB، `data:image` بس)، وفيه حقل honeypot مخفي بيصد البوتات. قراءة الشكاوى/تعديل حالتها/حذفها للأدمن بس (`x-admin-password`) لأنها بيانات شخصية، والـ POST العام بيرجع رقم المتابعة بس من غير ما يعيد أي بيانات.
